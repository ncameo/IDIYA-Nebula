# Proposed change CR-002 — bind the "Show active customers only" toggle (S-03 Customer Split View)

Status: **proposed, not applied**. Raised 2026-10-18 while adding the List form + Advanced Search form pair contract
(plugin v0.1.13/v0.1.14, check E14: every mapped `ApiParam` must be used by the read). Reverted from the project at
Paresh's instruction; nothing below is in the built forms.

## Why

The S-03 list cardgrid maps the search form's `activeOnly` checkbox to the API parameter `activeOnly`
(`advancesearchapimapping` + `ResultApiParam`), but the Cosmos `query` has no clause for it, so the toggle is inert.
Spec `A-07` note says: *"Search box and 'Show active customers only' toggle call the list endpoint (toggle = Status Active)."*
— the semantics are defined, so the parameter can be bound. Until it is, parity reports
`E14 6421b203:cardgrid[CustomerCard] ApiParam 'activeOnly' is not used as an @activeOnly placeholder`.

## Proposed edits (exact)

1. `ncameo/quzlglsembkgyxydataconnections/binding-profile.json` → `bindings.S-03`:
   - add `"filters": [{ "param": "activeOnly", "control": "activeOnly", "field": "Status", "value": "Active", "when": "true", "source": "A-07 note: toggle = Status Active" }]`
   - remove the `unbound` entry `{"operation": "list-filter", …}`
2. `ncameo/quzlglsembkgyxy/6421b203-cc6c-4acf-ae40-b3c83621641e.json` → cardgrid `CustomerCard.query`, one line before `ORDER BY`:
   ```
   AND ( '@activeOnly' != 'true' OR c.Status = 'Active' )
   ```
   (a checkbox sends `true` / `false`; only `true` narrows the result; the `advancesearchapimapping` / `ResultApiParam`
   entries already exist and stay as they are)
3. `ncameo/quzlglsembkgyxydataconfig/6e8ddfda-82da-4af1-b0d2-183da9723fa3.json` → regenerated by `dataconfig.py sync`
   (its `query` field follows the form).

## Alternative

Drop the mapping instead: remove the `activeOnly` entries from `advancesearchapimapping` and `ResultApiParam` and keep
the toggle inert (also satisfies E14). Not recommended — the spec defines the behaviour.

## Note on the new default rules (v0.1.14)

The S-03 search form carries a `customerFilter` button; new generation would not write it (warning W1). Existing forms are
left as they are — this is noted only so the next regeneration of S-03 is not a surprise.
