While configuring APIs for each form or control, ensure that a corresponding `dataconfigid` property is added alongside each API connection property.

**Rules:**

1. **Match the API connection property:** Identify each connection property, including properties with the `get`, `update`, or `action` prefixes.
2. **Add `dataconfigid` at the same level:** Add a `dataconfigid` property at the same level as the corresponding connection property in the form or control configuration. If the connection property has a prefix, the corresponding `dataconfigid` property must use the same prefix.
3. **Assign a GUID:** The value of each `dataconfigid` property must be a valid GUID.
4. **Preserve the GUID:** Once a GUID has been generated and assigned to a `dataconfigid` property, it must remain unchanged. Even if a user updates or modifies the form or control through a request, the existing GUID must be preserved.
5. **Generate only when missing:** Generate a new GUID only when the corresponding `dataconfigid` does not already exist. Never replace an existing GUID during subsequent updates.

**Example:**

If a form or control contains a `connection` property, add `dataconfigid` at the same level. If it contains prefixed connection properties such as `getconnection`, `updateconnection`, or `actionconnection`, add the corresponding `getdataconfigid`, `updatedataconfigid`, or `actiondataconfigid` property at the same level.

The key requirement is that every API connection has a corresponding GUID-based `dataconfigid`, and that GUID remains stable throughout all subsequent form or control modifications.
